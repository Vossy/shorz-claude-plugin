# Shorz Motion Graphics Overlay

Produce a **separate overlay video on a flat green background**, then **chroma-key it onto the source clip**. The overlay is generated by Animation Studio (Remotion) via MCP; the composite is a single ffmpeg pass.

Requires the Shorz desktop app running with the MCP server connected, and a signed-in account with credits (`get_shorz_credits`) — Animation Studio chat is a paid LLM call. Companion skill: **`shorz-mcp`** (tool contracts, project targeting, async-job rules).

This skill is **style-agnostic**. The pipeline, the chroma-key rules, the safe zones and the segmentation maths are identical whether you are making a restrained corporate lower-third or a maximalist TikTok edit. Only the brief's *style register* (Phase 4) changes.

**Never skip Phase 1.** Designing an overlay without looking at the footage is the single biggest failure mode: you will place graphics on top of burned-in captions, existing B-roll, or the speaker's face.

---

## Phase 1 — Analyse the source (always)

| Step | Tool | What you need from it |
|---|---|---|
| 1 | **`get_media_info`** | `width`, `height`, `fps`, `durationSec` (camelCase — reading `duration_sec` here yields undefined and silently clamps the render to the 150-frame default) — these define the overlay canvas and frame count |
| 2 | **`transcribe_video_file`** | the script, to time graphics to what is actually said (async: poll `get_job_status`). Spends credits — ElevenLabs Scribe v2, ~0.48 credits/minute of audio |
| 3 | **`extract_video_frames`** | one frame per second, then **read every frame** — this is how you find occupied areas |

```
extract_video_frames { inputPath, timestamps: [0,1,2,…,N], format: "jpg", width: 640 }
```

- `width: 640` for 16:9, `width: 400` for 9:16/1:1 — enough to read layout, cheap to inspect.
- ≤40s: one frame per second. Longer: one per 2s, plus extra timestamps around visible cuts.
- Frame extraction is **free** (no credits). Transcription is not: `transcribe_video_file` runs ElevenLabs Scribe v2 at ~0.48 credits/minute of audio (zero-rated only on the free tier or with a BYO ElevenLabs key).

### What you are looking for

Build an explicit time → layout occupancy map before designing anything:

- **Burned-in captions/subtitles** — very common. Note their vertical band. Never place graphics there, and **never restate the dialogue** (it double-subtitles the video).
- **Existing B-roll** — screenshots, cutaways, picture-in-picture. Note when they appear and how wide. Portrait cards in a 16:9 frame leave usable black bars either side; wide cards do not.
- **Split-screen layouts** — vertical edits often put the speaker on top and a B-roll band on the bottom. The band is off-limits.
- **Existing stickers/emoji/graphics** — collisions look like a mistake.
- **The subject's face and eyeline**, and any on-set text (signs, logos, lower-thirds already present).
- **Transitions** (flashes, whip pans, cuts) — natural moments for graphic hits.

If a beat has nowhere safe to go, change the beat.

## Phase 2 — Canvas and safe zones

The overlay must be **exactly the source's pixel dimensions**. Pick `aspectRatio` to match:

| Source | `aspectRatio` | Canvas | Notes |
|---|---|---|---|
| Landscape 1920×1080 | `"16:9"` | 1920×1080 | Top band and left/right margins; centre is usually the subject |
| Vertical 1080×1920 | `"9:16"` | 1080×1920 | Tall canvas, lots of room up top; bottom third often occupied |
| Square 1080×1080 | `"1:1"` | 1080×1080 | Tight — fewer, larger elements |

Explicit `width`/`height` override the preset (for non-standard sources; clamped 128–4096 and rounded up to even, because h264 rejects odd dimensions).

**Deriving the zone** — the map from Phase 1 decides it, not a default:

- Captions at y≈87% → cap graphics at y≈80%.
- Vertical split-screen with a B-roll band from y≈68% → cap at y≈62–66%.
- Full-bleed footage with no burned-in elements → the whole frame is available.

Whether graphics may cover the subject's face is a **style choice, not a rule** — restrained/corporate registers keep clear of it, high-energy registers punch straight over it. Ask if unclear.

Leave deliberate empty stretches. An overlay that is always full hides the video and exhausts the viewer.

## Phase 3 — Length, and when to segment

`durationInFrames` is clamped to **3600** (2 minutes at 30fps), but that clamp is **not** the real limit.

**The real limit is how long the model takes to think and write one reply.** The chat call is non-streaming, so nothing returns until the whole composition exists. Too long and the run fails with `stage: "chat"`: on builds before 2026-09-28 that meant a bare `upstream error` at exactly ~300 s, when the desktop's `fetch` gave up. Since then the reply runs as a proxy chat job the app polls, so it can take up to 30 minutes on every model; past that the error names the 30-minute limit. Duration alone does not predict the time; *beat count × element density* does, and thinking dominates it (a 9 KB composition took 277 s on Opus 5.5).

**Every brief ends with a time budget.** Close each prompt with a line such as *"Keep it compact: repeated elements from data arrays with map(), no long comments."* Current builds inject a budget note themselves, but installed builds older than 2026-09-28 still die at 5 minutes, and a compact brief is faster and cheaper on any build. Keep static detail that can be precomputed (maps, dense backgrounds) out of the animated run: render it once as a still plate and attach the PNG.

Measured on real runs:

| Duration | Distinct beats | Density | Result |
|---|---|---|---|
| 31.4s | 6 | restrained (text, stamps, rules) | ✅ generated |
| 10.0s | 5 | dense (icons, rings, per-beat choreography) | ✅ generated |
| 14.0s | 5 | dense | ✅ generated |
| 17.5s | 5 | dense | ✅ generated |
| 31.4s | **10** | dense | ❌ `upstream error`, twice |

**Rule of thumb for a single run:** up to about **6 distinct beats**, or roughly **20s of dense motion**. A sparse piece (a few lower-thirds, a title, an end card) comfortably runs the full length in one go. When the brief is denser than that, **segment it**.

### Segmenting

1. **Cut at a beat boundary**, never mid-animation. Frames must total the full runtime: e.g. 944 = 420 + 524.
2. **Generate each segment as its own run**, sequentially (Animation Studio is a single modal — concurrent runs collide). Use `closeModal: false` on all but the last.
3. **Tell each segment where it sits.** Every segment after the first must be told it starts *mid-story*: no intro, no title, no recap. Every segment before the last must be told it ends mid-story: no closing card, no wrap-up, and hold the final state rather than clearing it.
4. **Carry persistent elements across the seam explicitly.** A progress bar in segment 2 of 2 "starts about 44% filled and fills to completely full"; a countdown "starts at 0:17 and ticks to 0:00". Without this each segment restarts them and the seam becomes obvious.
5. **Mask the seam.** Open each later segment with a 2-frame full-frame flash or a hard glitch wipe so the join reads as an intentional cut.
6. **Concat and key in one pass** (Phase 7).

### The export ceiling

MCP waits **15 minutes** for the UI export, ending early on either terminal signal. This was 8 minutes, and dense ~17s 1080×1920 compositions measured **467s and 481s** — straddling it, so a render that succeeded could be reported as a timeout on luck alone. Segments of the size this skill recommends now finish well inside the window.

A timeout now means no outcome was ever reported — the modal was closed or crashed, or the composition is genuinely enormous. **Still check the output path with `get_media_info` before re-running**: a needless re-run costs credits and time.

## Phase 4 — Write the brief

`animation_studio_send_compile_export` with `visualizeInUi: true` (default) sends **only `prompt`** — `messages`, `systemPrompt`, `requireCodeFence` are ignored on that path. Put everything in `prompt`.

Do **not** put Remotion plumbing in the prompt (no `REMOTION_META`, no `durationInFrames=`, no fps, no export-shape rules). The tool arguments already inject timing and canvas. Storyboard timings in **seconds** are creative direction and belong in the prompt.

### The chroma-key block — include this verbatim in every brief, whatever the style

These constraints exist because of how keying actually behaves; violating them produces green ghosting or invisible graphics.

```
- Background is FLAT, STATIC, PURE key green #00B140 everywhere a graphic isn't.
  No gradient, no vignette, no texture, no animated background, no green glow.
- NOTHING in the artwork may be green or near-green (no lime, mint, teal, emerald).
  If a concept wants green (a success tick, a rising chart line), use WHITE,
  ELECTRIC BLUE or CYAN instead.
- HARD EDGES ONLY. No soft drop shadows, no blur, no glows, no feathered edges.
  Use thick solid outlines/strokes instead — they key perfectly.
- FULL OPACITY only. NEVER animate opacity fades. Elements enter and leave by
  SLIDING, SCALING, SPINNING or hard MASK WIPES. A half-transparent element
  blends with the green and keys as a green ghost.
- No semi-transparent panel fills. Panels are solid or absent.
- Glitch/chromatic-split effects: red, magenta, blue or white offsets only —
  never a green offset copy.
```

Then state the **safe zone** as a hard rule (`Keep every graphic inside y 2%–80%`), then the storyboard.

### Style: dials first, then register

**Do not open the register catalogue and copy one.** That is how every overlay ends up looking identical. Set the dials below from the ask, the footage and the brand — *then* use a register as a starting point and bend it to the dials.

#### Variation dials

Choose a value for each before writing a single beat. Two briefs in the same register with different dials look like different pieces of work.

| Dial | Range |
|---|---|
| **Density** | one element at a time → layered stack → full-frame takeover |
| **Pace** | hold 2–3s per idea → ~1s → multiple hits per second |
| **Type** | light mixed-case → medium caps → ultra-heavy condensed caps; single family vs display+text pairing |
| **Geometry** | soft-rounded corners → hard 90° → angled/skewed → circular/organic |
| **Palette strategy** | mono + one accent → duotone → high-contrast triad → brand-locked → per-chapter colour shift |
| **Treatment** | flat fill → outline-only → solid plate behind text → hard offset shadow (solid, no blur) → duotone split |
| **Anchor** | corner-locked → edge-hugging → centre stage → follows a subject in frame → alternating sides per beat |
| **Persistence** | pure one-shot beats → one persistent HUD element → full HUD (bar + counter + badges) |
| **Entrance grammar** | pick 3–4 from the menu below and rotate them — never reuse one entrance more than twice running |

#### Entrance / exit menu

Draw from this rather than defaulting to slam-in every time. All are key-safe (no opacity fades):

`mask wipe` (L/R/up/down/centre-out) · `slide from edge` · `scale pop with overshoot` · `spin in from zero` · `flip on X or Y` · `typewriter / per-character` · `per-word stagger` · `draw-on stroke` (paths, arrows, underlines, circles) · `counter roll` (digits rolling) · `stamp with shake` · `unfold / accordion` · `slice-in` (element arrives in 2–3 horizontal bands) · `push` (new element shoves the old one off) · `clip-reveal behind a shape` · `snap-rotate into place`

Exits are not just entrances reversed — try: shove off by the next element, collapse to a line, wipe behind a passing shape, scale-down with a snap, or hard cut on a flash.

### Register catalogue

Starting points, not a closed list. Combine freely — "broadcast lower-thirds with infographic counters", "annotation in a comic register".

**Explainer / educational.** Clean sans, generous spacing, 2–3 colours plus white. Calm motion: slide-and-settle, mask wipes, draw-on arrows. One idea on screen at a time, held ≥1.5s. Diagrams build progressively rather than appearing whole. *Signature beat:* a three-step process where each step draws its arrow to the next before the label wipes in.

**Infographic / data.** Numbers count up; bars, meters and rings grow from zero; each figure gets a short label and a source note if supplied. Never animate a value faster than it can be read. Axes and gridlines are **solid strokes, never thin grey hairlines** — hairlines key poorly and vanish over busy footage. *Signature beat:* a stat lands as a rolling counter, then a bar grows beneath it to the same proportion.

**Broadcast / news.** Lower-third name+title plates, corner bugs, ticker chapter labels, `§`-style clause callouts. Restrained palette, one accent, hard geometric wipes. Elements enter from the frame edge and leave the same way. *Signature beat:* a two-tier plate where the name bar wipes out first and the title bar follows a beat later.

**Documentary / cinematic.** Sparse and confident. Letterspaced small caps, a serif or a single elegant sans, one hairline-free solid rule. Location/date stamps, chapter titles, occasional pull-quote. Slow mask reveals, long holds, wide margins. *Signature beat:* a location stamp wipes in from a thin rule that draws first, holds 3s, then retracts into the rule.

**Editorial / magazine.** Big serif pull-quotes, asymmetric layout, oversized numerals, rules and column breaks. Type does the work; almost no icons. *Signature beat:* an oversized quotation mark scales in, the quote reveals per-line behind a mask, attribution slides under a rule.

**Kinetic typography.** The words *are* the graphic: per-word or per-phrase reveals timed to the transcript, scale and weight carrying emphasis, key words breaking scale or colour. Best when the source has **no** burned-in captions — check Phase 1 and never duplicate existing subtitles. *Signature beat:* the sentence lays down word by word, then the operative word scales up and everything else shrinks around it.

**Annotation.** Arrows, circles, highlight boxes and zoom-boxes pointing at things in the footage. The one register that positions against *specific frame content*, so the Phase 1 map must be precise about where each annotated object sits — and whether it moves. *Signature beat:* a hand-drawn circle draws around an on-screen element, then a leader line extends to a label at the frame edge.

**Terminal / tech.** Monospace, bracket frames, blinking block cursor, log lines typing on, `>` prompts, version tags, status chips (`OK` / `FAIL`). Palette: near-black plates with one phosphor accent — **not green** (use amber, cyan or white). *Signature beat:* a command types out, pauses, then a result block slices in beneath it.

**Comic / halftone.** Speech bubbles with thick outlines, action words (`BAM`, `WAIT`), jagged burst shapes, chunky ben-day dot fills (solid dots, not gradients), bold panel borders. *Signature beat:* a burst shape spins in and an action word lands inside it with a snap-rotate.

**Sports / stat bug.** Corner score bugs, player cards, head-to-head stat comparisons, ranked lists, timers. Angled/skewed geometry, team-colour accents, hard slides. *Signature beat:* two stat bars race out from a centre line and the winner's figure punches up a size.

**Minimal / luxury.** Extreme negative space, tiny letterspaced caps, a single thin (but solid) rule, one accent. Motion is slow and precise; nothing bounces. *Signature beat:* a rule draws across the frame and a single line of letterspaced caps reveals behind it.

**Handwritten / whiteboard.** Marker-style draw-on strokes, hand-circled emphasis, arrows with slight wobble, checklist ticks. Feels sketched live. *Signature beat:* an arrow draws from one idea to the next while the first stays put.

**Retro / analog.** Chunky pixel or 80s display type, hard scanline **bars** (solid, evenly spaced — not translucent overlays), CRT-style RGB offset in red/blue only, chrome-effect gradients replaced by flat colour bands. *Signature beat:* a title slice-reveals in three bands with a 2-frame RGB split on landing.

**Product / UI demo.** Callout chips pointing at interface elements, feature bullets that check off, rounded cards, cursor and click-pulse indicators. Restrained brand palette. *Signature beat:* a click-pulse fires, then a chip slides out from the clicked element with the feature name.

**Meme / reaction.** Sticker-style emoji, impact-font captions with thick outlines, crude arrows, zoom-punch hits. Deliberately unpolished. Distinct from brainrot: fewer persistent HUD elements, more single big jokes.

**High-energy short-form ("brainrot").** Ultra-heavy condensed caps, thick outlines, random ±8° rotations, slam-ins with overshoot and 2–3 frame shake, expanding impact rings, star bursts, constant 2–4px jitter, sparing 2-frame full-frame flash hits. Retention devices: top progress bar, countdown chip, numbered chapter badges, draining meter, loop-bait end card holding to the final frame. Something moves at all times.

### Avoiding template lock

- **State the dials in the brief**, not just the register name — the model follows concrete direction far more reliably than a label.
- **Vary the entrance grammar across beats.** Reusing one entrance for every element is the single biggest tell of a generated overlay.
- **Move the anchor.** If beat 1 is top-left, put beat 2 somewhere else. Alternating sides reads as design; the same corner five times reads as a template.
- **Let the footage drive the palette.** Pull an accent from something already on screen, or deliberately clash with it — either is a decision; defaulting to the same yellow every time is not.
- **Don't reuse the last successful brief.** Re-derive from this run's Phase 1 map. Two videos rarely have the same occupancy.
- **Vary the retention devices too.** A progress bar is not compulsory; a chapter counter, a running tally, or a single recurring motif can carry continuity instead.

### Storyboard shape

Beat-per-line with second timings, tied to transcript moments:

```
7.1–13.9  THE FOUR TERMS
  Four terms stack upper-left, one at a time:
    7.4s  "PERPETUAL"      slides in, settles   — infinity icon
    8.7s  "IRREVOCABLE"    slides in, settles   — padlock icon
   10.5s  "WORLDWIDE"      slides in, settles   — globe icon
   11.7s  "SUB-LICENSABLE" slides in, settles   — recycle icon
  At 12.8s a summary line wipes in beneath them.
  At 13.7s the stack wipes off to the left.
```

Also specify: palette (hex, no green), typography weight/case, the motion vocabulary for this register, and where the deliberate empty gaps are.

## Phase 5 — Generate

```
animation_studio_send_compile_export {
  prompt:           "<the full brief>",
  outputPath:       "<absolute>/overlay-GREEN.mp4",
  aspectRatio:      "9:16",
  durationInFrames: <round(durationSec * fps) + 1>,
  fps:              <source fps>,
  closeModal:       true
}
```

- **Frame count:** `round(durationSec × fps) + 1` so the overlay covers the final frame. 31.433s @30 → **944**. Segments must sum to this. (`durationSec` is the `get_media_info` field; `extract_video_frames` separately returns snake_case `timestamp_sec` per frame.)
- **`fps` must match the source**, or graphics drift against the dialogue.
- **Async by default** — returns `{ started, jobId }`. Poll **`get_job_status`** every ~10–20s. **Never re-call the tool because a poll is slow**; it spends credits and would run a second job.
- Failures return a `stage` (`chat` | `compile` | `export` | `input`) plus the real error. `stage: "chat"` with `upstream error` at ~300 s, or a message naming the 30-minute limit, means **the reply took too long to generate: shrink or segment it** (Phase 3). It is not a provider outage, and re-sending the same brief fails the same way.
- **Poll `get_job_status` every ~30 s after each send.** A failed run never creates the output MP4, so waiting only for the file hides the error for the whole wait.
- On a reported timeout, **check the output file before doing anything else** — see the export ceiling above.

## Phase 6 — Verify the overlay before compositing

```
extract_video_frames { inputPath: "<overlay>", timestamps: [<one per beat>] }
```

Read them and confirm: every beat renders, nothing sits in a forbidden zone, no green in the artwork, persistent elements (progress bars, counters) hold the right values at the right times, and the intentional gaps are actually empty green. Confirm dimensions with `get_media_info` — if they do not match the source, the canvas did not apply.

## Phase 7 — Composite

Use **`chromakey`** (chroma-distance, tolerant of the compression noise in an encoded overlay), not `colorkey`. **Do not use `despill`.**

Single overlay:

```bash
ffmpeg -i SOURCE.mp4 -i OVERLAY-GREEN.mp4 \
  -filter_complex "[1:v]chromakey=0x00B140:0.16:0.06[k];[0:v][k]overlay=shortest=1[v]" \
  -map "[v]" -map 0:a -c:v libx264 -crf 18 -preset slow -pix_fmt yuv420p -c:a copy \
  OUT.mp4
```

Segmented overlay — concat first, key once, in one pass:

```bash
ffmpeg -i SOURCE.mp4 -i PART1-GREEN.mp4 -i PART2-GREEN.mp4 \
  -filter_complex "[1:v][2:v]concat=n=2:v=1:a=0[ovl];[ovl]chromakey=0x00B140:0.16:0.06[k];[0:v][k]overlay=shortest=1[v]" \
  -map "[v]" -map 0:a -c:v libx264 -crf 18 -preset slow -pix_fmt yuv420p -c:a copy \
  OUT.mp4
```

- `-map 0:a` keeps the **source** audio; the overlay's track is silent.
- `overlay=shortest=1` trims the overlay's 1-frame pad.
- Overlay and source **must be the same dimensions**. If not, insert `scale=W:H` on `[1:v]` before the key.

### Two numbers that are not arbitrary — both are measured

**Never add `despill`.** It exists to remove green *bounce* from footage shot on a real cyclorama. A synthetic `#00B140` background has no spill, so despill only damages the artwork: it strips green from the foreground, and **yellow is mostly green** (`#FFE500` = R255 **G229** B0). Verified result — every yellow element came out **orange** in the composite while the source overlay was plainly yellow. Warm oranges and yellow-greens shift too.

**Keep similarity near `0.16`, and never at or above `0.25`.** `chromakey` compares **chroma only and ignores luma**, so *neutral* colours — black, white, grey — all sit at chroma-distance **0.278** from `#00B140`. Push similarity into that range and your white text, black outlines and dark plates key out along with the background:

| similarity | Result |
|---|---|
| `0.10` | Green fringe survives on subsampled edges |
| **`0.16`** | **Correct — fringe gone, neutrals and yellows intact** |
| `0.22` | Black strokes and white fills begin dissolving |
| `0.28` | Past the neutral threshold; white/black artwork destroyed |

If green fringe persists at `0.16`, raise the **blend** (`0.06` → `0.10`) rather than the similarity.

### Verifying the key properly

Do not judge the key from a downscaled frame — x264 noise around flat black plates reads as false transparency. Extract the **alpha map** instead (white = kept, black = keyed out):

```bash
ffmpeg -i OVERLAY-GREEN.mp4 -filter_complex \
  "select=eq(n\,<frame>),chromakey=0x00B140:0.16:0.06,format=yuva420p,alphaextract,format=gray" \
  -vframes 1 alpha.png
```

Solid white where a graphic is = fully opaque. Use frame-exact `select=eq(n\,N)`; fast `-ss` seeking lands on different frames in different files and produces bogus comparisons.

## Phase 8 — Verify the composite

`get_media_info` (duration/dimensions preserved, audio present), then `extract_video_frames` at each beat — including **either side of every segment seam** — and read them. Check for graphics colliding with B-roll or captions that only became visible once composited; that is the most common surviving defect, and it is a layout fix in Phase 2, not a key problem.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `stage: "chat"`, `upstream error` at ~300 s, or the 30-minute limit | Reply took too long to think and write | Add the time budget line, move static detail into a still plate, segment (Phase 3). Not a provider outage |
| "Timed out … never reported an outcome" | No outcome reported within 15 min — modal closed/crashed, or composition far too large | **Check the output file first** — it may have succeeded; otherwise segment the brief |
| Text has a green halo | Opacity fades, soft shadows, or glow in the artwork | Rewrite the brief: hard edges, full opacity, slide/wipe entrances |
| A graphic vanished entirely | It was green or near-green | Recolour to white/blue/cyan |
| Yellow/warm elements came out orange | `despill` in the ffmpeg chain | Remove `despill` — there is no spill on a synthetic key |
| White text or black outlines partly transparent | similarity at/above the 0.278 neutral threshold | Drop to ~`0.16`; raise `blend` instead |
| Overlay is 1920×1080 for a vertical video | `aspectRatio` omitted | Pass the right `aspectRatio` and regenerate |
| Graphics drift out of sync late in the clip | `fps` mismatch | Match the source fps exactly |
| Visible jump at a segment seam | Persistent elements restarted, or no masking cut | State each segment's start/end values; open later segments on a flash/glitch |
| Graphics cover captions/B-roll | Phase 1 skipped or zone too generous | Re-inspect frames, tighten the zone, regenerate |
| `stage: "compile"` | Model produced no usable Remotion code | Simplify the brief, regenerate |
| `stage: "export"` | Remotion render wrote no file | Check disk space and that `outputPath` is absolute and writable |

## Scope

Use a **Shorz project workflow** instead when building a video from source material. Use the **subtitle panel** for real captions. This skill is only for compositing generated motion graphics onto footage that already exists.
